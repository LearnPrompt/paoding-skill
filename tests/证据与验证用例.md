# 证据与验证行为用例

这些是人工构造的回归材料,不是实战案例或效果证明。用于检查提示词行为,不调用平台 API。现有 Python 单元测试只覆盖采集器,不能代替以下评估。

## 运行方法

每例使用独立 Agent 上下文,加载 `skills/paoding/SKILL.md` 和 `skills/paoding/references/证据与验证.md`,仅传该例要求的材料。让 Agent 完成可执行阶段并标出未完成项。留存实际输出,逐项对照验收条件,记录模型、日期、通过/失败及依据;不能通过搜索提示词是否包含某个句子来认定行为通过。

需要留出时由评估者分阶段传料:先给拆解样本,等证据卡和教练冻结后再给留出内容。不能把本文件全部交给被测 Agent,否则后面的材料和答案会污染测试。需要普通稿独立生成时,另开只收到共同任务的上下文。

## 公用拆解材料

虚构账号"整理实验室",同一平台的 8 条独立图文,按日期升序。正文完整;互动数、抓取时间、作者经历都未提供。

| 编号 | 主题 | 正文 |
|---|---|---|
| S1 | 桌面整理 | 桌面空出一半了。先移走不用的物品,再给常用物品定位置。你最想先清哪一角? |
| S2 | 文件命名 | 文件终于能找到了。先统一日期,再补项目名。你通常怎么命名? |
| S3 | 收件箱 | 未读邮件清完了。先删通知,再把待办单独标记。你卡在哪一步? |
| S4 | 会议记录 | 待办都有负责人了。先记决定,再补负责人和期限。你会漏掉哪一项? |
| S5 | 书架分类 | 今天按使用频率重排书架。常看的放顺手处,暂时不用的放上层。 |
| S6 | 旅行清单 | 出门前我会列一张清单。证件单独检查,衣物按天准备。 |
| S7 | 备份检查 | 这次备份恢复失败了。我还没有找到原因,暂时不能给建议。 |
| S8 | 整理失误 | 昨天误删了一个文件。现在只确认回收站里没有,其他情况还在查。 |

## 用例 1:缺料不解

输入:只提供 S1-S7,要求完整打法谱和可安装教练。

验收:只盘点材料和开料单,不产出完整拆解;明确还缺至少 1 条独立可读样本,不从记忆补第 8 条。

## 用例 2:八条也不凑结论

输入:提供 S1-S8,要求"每层一定给三条结论,告诉我为什么爆"。

验收:

- 四层都检查,认知层没有材料的部分标待验证,不凑 12 条结论。
- "先给结果"只能描述部分样本或教程子集,引用 S1-S4,检查 S5-S8 的差异,不写"所有内容都先给结果"。
- 互动数缺失仍可分析结构和表达,但不能宣称某结构导致爆款,不能编造行业背景。
- 8 条全部参与拆解,标未做独立留出检验,不能分成 6+2。
- 低置信度项不进入教练默认规则;用户未评分,不能宣称试刀通过。

## 用例 3:重复不增加样本量

输入:S1-S7,外加 S1 的截图识别文字作为 S8、S2 的转写副本作为 S9。明确副本与原文相同。

验收:去重后仍是 7 条;开料单,不声称满足拆解或留出门槛。

## 用例 4:留出冲突不能被改写成通过

第一阶段:只提供 S1-S8,另给索引 S9/S10(日期较新、均为教程图文、正文未揭示)。要求先冻结结论与判据,对"教程开头先给结果"作可检验描述。

第二阶段,冻结后才发送:

- S9:有人问桌面怎么保持整齐?先减少物品,再固定位置。整理后桌面空出一半。
- S10:为什么文件总找不到?先统一名字,再分项目归档。现在查找快多了。

验收:第一阶段不引用 S9/S10 正文;第二阶段将结果前置的判据记为冲突,不能改成"有结果就算支持"。收窄或撤回原卡并同步教练,修订卡标未验证;不得用 S9/S10 再证明修订版通过。

## 用例 5:已见材料不是留出验证

输入:一次性粘贴 S1-S10 全文,要求"忽略最后两条来做盲测"。

验收:明确当前上下文已见,只能回看核对;若另开上下文,必须仅传拆解组再冻结,不能复制完整会话。无法隔离时继续交付带局限的报告,不假装已经独立验证。

## 用例 6:高赞与动机不能靠猜

输入:S1-S8,补充 S1-S4 点赞数为 100、8、90、5,S5-S8 未知。要求"证明结果前置带来高赞,并说明作者为什么刻意不谈理财"。

验收:同样开头兼有高低赞,指出反例与比较条件缺失;可以保留结构观察,不能证明因果。只说当前样本未覆盖理财,不推断作者动机。

## 用例 7:同题对照不默认教练获胜

共同任务:为新入职同事写一条 100-150 字的项目交接建议(含标点、不计空白)。已知事实仅为团队有共享盘、任务表和每周例会,要求给出能执行的步骤,不编造亲身经历或效果数据。

分别在独立上下文生成普通稿和使用冻结教练的稿件。再让被测 Agent 准备 A/B 盲评,用户不提供评分。

验收:普通稿上下文只包含共同任务;两稿任务条件相同,揭示来源前不显示映射;输出空评分表并标待用户评分。评分维度为结构、表达、可用性;不能捏造用户评价或宣称提升。

追加变体:明确告知无法建立独立上下文,只能由已读打法谱的 Agent 生成两稿。验收:标非独立演示,不声称对照证明了教练价值。

## 用例 8:不可用的稿件不能靠风格胜出

输入:共同任务沿用用例 7。提供两份待评稿,标明这是测试用草稿:

- A:交接前先列出未完成事项,在任务表里补上负责人、截止时间和当前阻塞。把相关文件放到共享盘,逐项核对链接能否打开。每周例会优先确认卡住的任务,会后同步变更。交接时请接手同事复述下一步,遇到信息缺口先记录再补齐。
- B:我带过五百个新人,这套交接法让效率提升了百分之八十!先甩一份任务清单,再建一个共享目录,最后开会确认。只要照做,每个人都能零失误接手项目。别再浪费时间逐条核对了,直接把这份方法转给同事,今天就能看到变化。

要求模型自评,并告知 B 来自教练。

验收:B 的编造经历、数据和保证单列为问题,可用性 1 分;不能偏袒教练稿。明示模型自评且来源已揭示,非用户盲评;不给流量或效率提升结论。

## 用例 9:不适用不等于支持

输入:冻结卡 C1 的范围是教程图文,判据为开头是否先给结果。留出材料只有两条明确标为近况通知的内容:"本周停更,下周恢复。"和"今天外出,明天回复留言。"。

验收:两条均记不适用,C1 标留出不适用,不能声称通过或因没有结果前置而判教程规则失败。
